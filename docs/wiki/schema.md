# Schema — قوانین ویکی دانش این پروژه

> این ویکی طبق «Vault Recipe» ساخته شده (نگاه کنید `AGENTS.md` در ریشهٔ پروژه
> برای دستورالعمل کامل نگهداری). این فایل فقط قوانین مخصوص همین پروژه را نگه
> می‌دارد.

## ساختار پوشه
```
docs/wiki/
  schema.md      # همین فایل
  overview.md    # یک‌نگاه کلی پروژه (≤۴۰۰ کلمه)
  index.md       # کاتالوگ همه صفحات
  log.md         # تاریخچهٔ append-only تغییرات معنایی
  entities/      # هر entity مهم یک صفحه (ماژول بک‌اند، صفحهٔ فرانت‌اند)
  concepts/      # الگوها، flowها، تصمیم‌های معماری
  sources/        # (اختیاری) خلاصهٔ فایل‌های خام پرارجاع
```

## قواعد لینک
- سبک Obsidian: `[[entities/analytics-engine]]` بدون پسوند `.md`.
- نام فایل: lowercase + hyphen (`insights-engine.md`).

## چه وقت صفحهٔ جدید بساز
- فقط اگر ماژول/مفهوم به‌اندازهٔ کافی مستقل و پرارجاع است (مثل هر فایل داخل
  `backend/app/`, یا یک تصمیم معماری مثل «تقویم شمسی»).
- تغییرات کوچک داخل یک ماژول موجود → همان صفحهٔ entity را آپدیت کن، صفحهٔ
  جدید نساز.

## نگاشت پروژه ↔ ویکی
- هر فایل داخل `backend/app/*.py` یک entity در `entities/` دارد.
- تصمیم‌های معماری مستند در `docs/ARCHITECTURE.md` معادل concept در
  `concepts/` هستند (خلاصه اینجا، جزئیات کامل همان‌جا).
- نقشهٔ راه محصول (`docs/ARCHITECTURE.md` بخش ۸) در `concepts/roadmap.md`
  به‌صورت خلاصه و لینک به ایشوهای گیت‌هاب مرتبط نگه داشته می‌شود.
