# Overview — چرا (Chera)

«چرا» یک دستیار هوش مصنوعی تصمیم‌سازی از روی داده است: کاربر یک فایل CSV/Excel
(فروش، هزینه، عملیات) آپلود می‌کند و به فارسی سؤال می‌پرسد؛ سیستم بدون SQL و
بدون صف انتظار تیم فنی جواب می‌دهد چه اتفاقی افتاده، چرا افتاده، و کدام دسته
بیشترین سهم را در تغییر داشته.

## معماری در یک نگاه
```
Frontend (Vanilla JS + Chart.js, بدون build)
   │ HTTP/JSON
   ▼
FastAPI Backend
   ├─ datastore.py   ← آپلود/ذخیره (pickle روی دیسک، MVP تک‌کاربره)
   ├─ nlu.py         ← تحلیل سؤال فارسی → intent (قانون‌محور، نه LLM)
   ├─ analytics.py   ← موتور تجمیع/گروه‌بندی/تجزیهٔ تغییر/روند
   ├─ insights.py    ← موتور بینش خودکار (بدون سؤال، خودش یافته پیدا می‌کند)
   ├─ jalali.py       ← تبدیل و گروه‌بندی تاریخ شمسی
   └─ schemas.py      ← مدل‌های Pydantic ورودی/خروجی API
```

## چرا rule-based، نه LLM؟
تصمیم عمدی MVP: صفر هزینهٔ API، تأخیر کم، رفتار قابل‌پیش‌بینی و قابل تست واحد.
محدودیت شناخته‌شده: سؤال‌های آزاد/چندمرحله‌ای پوشش داده نمی‌شوند — لایهٔ LLM
مکمل در نقشهٔ راه فاز ۳ برنامه‌ریزی شده (نگاه کنید [[concepts/roadmap]]).

## دو مسیر پاسخ به کاربر
1. **پاسخ به سؤال صریح** (`POST /api/ask`) → `nlu.py` سؤال را parse می‌کند و
   یکی از توابع `analytics.py` را صدا می‌زند.
2. **بینش خودکار بدون سؤال** (`GET /api/datasets/{id}/insights`) → بلافاصله
   بعد از انتخاب دیتاست، `insights.py` مهم‌ترین یافته‌ها را خودش پیدا می‌کند
   (روند غیرعادی، تمرکز یک دسته، گروه دورافتاده، کیفیت داده). جزئیات:
   [[entities/insights-engine]].

## تاریخ شمسی — نکتهٔ معماری مهم
داده‌های ایرانی معمولاً تاریخ شمسی دارند؛ چون `pandas.Timestamp` فقط سال‌های
میلادی را می‌فهمد، همه‌چیز قبل از تحلیل به میلادی تبدیل می‌شود و گروه‌بندی
ماهانه روی مرز واقعی ماه شمسی انجام می‌شود، نه میلادی. جزئیات:
[[concepts/persian-date-handling]].
