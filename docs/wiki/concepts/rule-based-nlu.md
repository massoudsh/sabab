# Rule-Based NLU (تصمیم معماری)

> چرا موتور پاسخ‌دهی فعلی قانون‌محور است، نه LLM.

## تصمیم
برای MVP، هیچ فراخوانی به یک LLM خارجی در مسیر پاسخ‌دهی وجود ندارد.
[[entities/nlu-engine]] الگوهای رایج سؤال فارسی را با کلیدواژه + fuzzy
matching تشخیص می‌دهد و مستقیم روی `pandas.DataFrame` اجرا می‌کند.

## مزیت
هزینهٔ صفر، تأخیر خیلی کم، رفتار قابل‌پیش‌بینی، قابل تست واحد بدون mock کردن
API خارجی.

## محدودیت شناخته‌شده
سؤال‌های آزاد، چندمرحله‌ای یا مبهم پوشش داده نمی‌شوند و به `fallback` می‌روند.

## مسیر رشد (گام بعدی NLU)
لایهٔ `parse_question` طوری طراحی شده که وقتی intent برگشتی `fallback` بود،
بتوان سؤال + schema دیتاست را به یک LLM داد تا کد pandas/SQL امن تولید کند
(با sandbox و whitelist توابع مجاز — هرگز اجرای مستقیم کد آزاد کاربر یا خروجی
مدل بدون sandbox). نتیجه در همان قالب `AskResponse` برمی‌گردد تا فرانت‌اند
تغییری نخواهد. نگاه کنید [[concepts/roadmap]] فاز ۳.

## همین الگو در موتور بینش
[[entities/insights-engine]] هم عمداً همین فلسفه را دنبال می‌کند: کاملاً
قانون‌محور و رایگان، بدون فراخوانی LLM.
